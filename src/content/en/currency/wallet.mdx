# Wallet, redemption codes and transactions

Wallet shows your TDC balance. Transactions explains balance changes. Top-up Records tracks external payments made to obtain TDC.

## Available and frozen balances

Available balance is currently spendable. Frozen funds are reserved by a business operation and cannot be spent again; a hold does not itself mean a completed debit.

Before payment, ensure the available balance covers the order's final charge, including applicable fees. Afterward, refresh the wallet and find the corresponding debit in Transactions.

## Using a redemption code

If you hold a valid code issued through the platform:

1. Open the redemption-code area in Wallet.
2. Enter the code and submit once.
3. After success, refresh the balance and check the corresponding transaction.
4. If the code is invalid, used or unavailable, check your input and contact its issuer.

A redemption code is not a general discount coupon and does not directly pay an existing product order. Do not expose the complete code in screenshots, group chats or support requests.

## Three types of records

| Record | Question it answers |
| --- | --- |
| Top-up record | Which external top-up is pending, successful or closed? |
| Product order | What was bought, was it paid, and how is delivery progressing? |
| Wallet transaction | Which credit or debit changed the TDC balance? |

One operation can produce both an order and a wallet transaction. Related records do not imply duplicate charging. Merchant revenue is checked in the merchant owner's wallet and transactions too.

## Investigating a mismatch

Check the account, currency, time filter and business number first. An external charge may include fees, while TDC credit uses the conversion saved for that top-up or order. The numerical values need not match.

If a top-up returns to the platform without a balance change, check its confirmation status. If an order is paid but not delivered, check [order status](/en/shopping/orders/). Do not top up or pay again to force a status refresh.

The public interface does not currently offer complete withdrawal, user-to-user transfer or self-service refund flows. A balance or exchange-rate display does not establish that these features are available.
