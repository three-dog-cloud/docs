# OAuth 客户端与密钥

OAuth 客户端表示一个请求用户授权或调用 OpenAPI 的应用。申请时最容易混淆的是客户端类型和 `client_secret`。

## 公共客户端与机密客户端

| 类型 | 适用场景 | Client Secret | 推荐流程 |
| --- | --- | --- | --- |
| 公共客户端 | 浏览器单页应用、移动端、桌面应用 | 不签发 | Authorization Code + PKCE |
| 机密客户端 | 有独立后端、能在服务器安全保存配置的应用 | 签发并校验 | Authorization Code + PKCE；符合条件时可用 Client Credentials |

公共客户端不是“安全级别较低的 Secret”。它从设计上就没有可长期保密的位置，因此平台不依赖 Secret 验证它，而是强制使用 PKCE 保护授权码。

## 四种容易混淆的值

| 值 | 是否可公开 | 用途 |
| --- | --- | --- |
| `client_id` | 是 | 标识哪一个应用发起授权 |
| `client_secret` | 否 | 机密客户端在令牌端点证明应用身份 |
| `access_token` | 否 | 代表用户或客户端调用被授权的 API |
| JWT 签名密钥 | 否，且只由平台掌握 | 平台签发和校验令牌 |

HTTPS 负责客户端与平台之间的传输加密。`client_secret` 不用于加密业务数据，也不能替代 HTTPS 或数据库加密。

## Secret 的保存与轮换

- 只把 Secret 放在服务端的密钥管理或环境配置中。
- 不要放进 Vue/React 构建产物、移动端安装包、公开仓库或日志。
- 平台仅保存 Secret 的不可逆哈希，不能找回原值。
- 轮换后新 Secret 只显示一次，请立即保存。
- 发现泄露时立即轮换；旧 Secret 随即失效，服务端配置也需要同步更新。

## 回调地址规则

授权结果只会返回到客户端申请时登记的精确回调地址：

- 生产地址必须使用 HTTPS；
- `localhost` 与 `127.0.0.1` 可在本地开发时使用 HTTP；
- 地址不能包含 URL fragment（`#...`）；
- 发起授权和换取令牌时的 `redirect_uri` 必须完全一致。

不要使用开放重定向页面作为回调地址，也不要把授权码写入日志。
