# 授权码与 PKCE

平台要求所有用户授权客户端使用 Authorization Code + PKCE（S256）。即使是机密客户端，也不能省略 PKCE。

## 1. 生成 PKCE 与请求状态

客户端本地生成：

- `code_verifier`：43 到 128 个允许字符组成的随机字符串；
- `code_challenge`：`BASE64URL(SHA256(code_verifier))`，不带填充；
- `state`：防止跨站请求伪造并关联发起请求；
- `nonce`：请求 `openid` 时必填，用于校验 ID Token。

`code_verifier`、`state` 和 `nonce` 必须保存在发起授权的会话中，不要发送给无关第三方。

## 2. 打开授权页

```text filename="授权请求 URL"
{PLATFORM_URL}/oauth/authorize
  ?response_type=code
  &client_id={CLIENT_ID}
  &redirect_uri=https%3A%2F%2Fapp.example.com%2Foauth%2Fcallback
  &scope=openid%20profile
  &state={RANDOM_STATE}
  &nonce={RANDOM_NONCE}
  &code_challenge={S256_CHALLENGE}
  &code_challenge_method=S256
```

用户登录后会看到应用信息、请求的 Scope 和回调地址，并选择同意或拒绝。成功时回调地址获得 `code` 与原始 `state`；拒绝时获得 `error=access_denied`。

收到回调后必须先验证 `state`，再使用授权码。授权码有效期为 5 分钟且只能使用一次。

## 3. 换取令牌

```bash filename="换取令牌"
curl -X POST "{API_BASE_URL}/oauth/token" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  --data-urlencode "grant_type=authorization_code" \
  --data-urlencode "client_id={CLIENT_ID}" \
  --data-urlencode "code={AUTHORIZATION_CODE}" \
  --data-urlencode "code_verifier={CODE_VERIFIER}" \
  --data-urlencode "redirect_uri=https://app.example.com/oauth/callback"
```

机密客户端还必须提交：

```text filename="机密客户端参数"
client_secret={CLIENT_SECRET}
```

成功响应包含 `access_token`、`refresh_token`、`id_token`、`token_type`、`expires_in` 和实际授权的 `scope`。

## 4. 获取用户信息

```bash filename="读取用户信息"
curl "{API_BASE_URL}/oauth/userinfo" \
  -H "Authorization: Bearer {ACCESS_TOKEN}"
```

`openid` 提供稳定的成对主体标识 `sub`；同时获得 `profile` 时，响应会包含平台允许公开的基础资料。应用应以 `sub` 关联本地账户，不要依赖用户名作为唯一标识。

## 5. 刷新令牌

```bash filename="刷新令牌"
curl -X POST "{API_BASE_URL}/oauth/token" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  --data-urlencode "grant_type=refresh_token" \
  --data-urlencode "client_id={CLIENT_ID}" \
  --data-urlencode "refresh_token={REFRESH_TOKEN}"
```

机密客户端同样提交 `client_secret`。Refresh Token 使用后会被消费并返回一组新令牌，请以新值原子替换旧值，不要并发重复刷新。

## 错误处理

OAuth 错误使用标准形态：

```json filename="OAuth 错误响应"
{
  "error": "invalid_grant",
  "error_description": "..."
}
```

常见错误包括 `invalid_request`、`invalid_client`、`invalid_grant`、`invalid_scope`、`access_denied`、`invalid_token` 和 `insufficient_scope`。不要把完整 Token、Secret 或授权码记录到错误日志。
