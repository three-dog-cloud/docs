# 商户订单与对账

“商户订单”包含“收款订单”和“商品订单”两个分类；“我的订单”展示当前账户作为买家的购买记录。同一个账户兼具两种身份时，先确认自己查看的是哪一类记录。

## 查看外部收款与冻结款

进入 **商户中心 → 订单 → 收款订单**，按 TDCloud 收款单号或外部商户订单号查询。开放平台按金额创建的收款单在此显示，不会自动生成 TDCloud 商品订单；店铺商品的销售记录在“商品订单”分类。

收款订单展示原币金额、支付状态、TDC 结算金额、冻结状态及预计解冻时间。点击商户订单号可查看本单锁定的折算结果、已转入可用余额的金额、欠款或额度抵扣和稳定支付事件号。按订单创建时保存的金额结算，付款、解冻和查单均不会使用当前汇率重算旧单。

页面分别显示钱包可用余额、收款冻结余额和担保金。“已入账 · 冻结中”表示收款已经结算到钱包，但尚不能使用，不应因此重复补账。收款冻结余额不包含担保金；投诉、退款或欠款抵扣可能影响实际解冻时间和最终可用金额。测试收款会标注“测试支付”。

## 每笔订单检查什么

| 信息 | 用途 |
| --- | --- |
| 订单号、商品、数量 | 定位销售记录和交付对象 |
| 买家实际支付与币种 | 确认买家侧付款，不直接作为商户收入 |
| 订单状态、付款时间 | 区分未付款、交付处理中、已完成和已取消 |
| 商户收入、入账状态 | 确认该笔销售是否形成钱包收入 |
| 收入交易编号 | 关联钱包流水，核对余额变化 |

不要只看订单总数、销量或“已完成”标签来判断收入。金额关系见[支付与结算](/zh/merchant/payments/)。

## 日常对账顺序

1. 按订单号找到对应商户订单。
2. 核对付款状态和付款时间。
3. 核对商品净价与商户收入，注意优惠、手续费及币种差异。
4. 在交易记录中找到相关收入流水，检查变动前后余额。
5. 分别确认实际商品交付和收入入账。

一笔订单可能已经付款但仍待交付；交付完成和财务入账应分开核对。

## 配置了交付回调时

支付成功后的业务回调可能重复到达。自己的接收端应按订单号去重，避免重复开通服务或发放商品。平台会使用稳定的请求头：

~~~http
Idempotency-Key: order-fulfillment:ORDER_NO
~~~

当前通知体包含 `order_no` 和 `callback_no`。这个去重键用于识别重复投递，不是签名或身份凭证；接收端需要单独确认可信来源，不能因为请求带了这个头就直接发货。

接收端应返回 HTTP 200 表示本次处理成功；当前平台不会把其他 2xx 状态一概当作成功。请求超时约 3 秒，耗时业务应可靠记录任务，并在自己的服务内跟踪后续执行。

业务处理结果应先可靠保存，再确认成功；外部副作用可能在网络失败前已经发生，因此重新收到通知时先查本地处理记录。

## 异常订单如何处理

- 待支付：不要提前发货，等待付款确认。
- 已付款待交付：检查接收服务是否可用、是否已按订单成功处理，再观察后台重试。
- 已取消：不要继续引导买家支付旧订单；取消记录可用于追溯库存释放。
- 已付款未入账：提供订单号和收入记录缺失情况，请平台核对。
- 实际交付不一致：记录已经发放的内容和时间，避免人工处理与自动重试重复发货。

联系支持时使用[问题反馈信息清单](/zh/getting-started/notifications/)，不要发送回调服务密钥或客户密码。
