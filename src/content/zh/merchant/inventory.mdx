# 卡密库存管理

库存中心用于独立管理“本地独占卡密”商品，入口为 **商户中心 → 库存管理**。普通账户必须先通过商户审核且商户处于启用状态；未开通时页面会显示入驻提示，而不是把它当成接口 404。

## 库存与商品的关系

一份卡密库存同时是一个可销售商品的供货实体，商品记录提供名称、价格、支付方式和销售入口，库存明细提供实际可交付内容。因此，本地卡密库存一定关联一个商品，但普通数量商品和 API 发货商品不一定拥有本地卡密库存。

可以从库存中心点击“新增卡密库存”，也可以先在商品页新建“本地独占卡密”商品。两个入口最终创建的是同一个关联对象，不要求经营者先手工完成某个页面；但导入卡密前，平台必须先保存商品记录，以便确定归属、价格和库存隔离范围。

## 新建与导入

1. 在库存中心点击“新增卡密库存”，填写商品资料并保存；首次创建默认不直接上架。
2. 进入该库存的管理页，粘贴卡密或选择 UTF-8 编码的 TXT 文件，一行表示一个可销售单位。
3. 先执行预检，核对有效、空白、重复和格式错误行；存在格式错误时不能确认入库。
4. 确认后再查看可售数量，完成价格、限购和支付方式检查后上架。

TXT 文件采用严格 UTF-8 校验，非法编码会被拒绝，不会用替换字符悄悄改写卡密。相同商品下的重复内容不会再次入库，已售出或已停用的内容也计入重复检查。

## 数量与批量购买

一行卡密对应一个库存单位。买家一笔订单购买 `8` 件时，平台会在同一订单中预留并交付 `8` 条不同卡密；可售数量不足时整笔下单失败，不会只交付部分数量。待付款订单会占用对应数量，取消或超时后才释放。

商品页显示的可售数量来自库存明细汇总，本地卡密模式下不能直接手改库存数字。库存暂时为零只表示售罄，不会自动改变商户主动设置的上下架状态。

## 库存状态

| 状态 | 含义 | 可再次销售 |
| --- | --- | --- |
| 可售 | 已入库且尚未分配 | 是 |
| 预留 | 已被订单占用，尚未完成交付 | 否 |
| 已交付 | 已写入买家可读取的交付记录 | 否 |
| 停用 | 人工停止销售并保留原因 | 否 |

库存页可以按状态和导入批次筛选、受控查看内容、停用或恢复可售条目。批量停用只处理提交时仍为可售的条目，并逐项返回成功或失败；不会强行撤销已经预留的订单。已交付内容不能恢复销售。

## 付款与交付

付款确认后，平台通过持久发货任务完成交付。订单详情会展示分配给当前买家的卡密；普通库存列表和其他买家的订单不能读取。重复付款通知或任务重试会返回原交付结果，不会再次选取新卡密。

如果付款已确认但交付任务失败，后台可查看尝试次数和最后错误，并进行重试或隔离。商户不应通过停用预留卡密来绕过异常处理；需要售后时请保留订单号和库存关联记录。
