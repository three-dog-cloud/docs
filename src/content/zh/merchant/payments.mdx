# 支付与结算

买家付款金额、商户收入和钱包余额是三个需要分别核对的数值。商户订单与交易记录用于确认实际发生的结算。

## 支付渠道与商户设置

商品可以使用平台提供且当前启用的 TDC 或在线支付渠道，具体以商品支付方式和报价为准。

在 **商户中心 → 支付与结算** 可设置是否允许未登录消费，并查看平台分配的冻结期、担保金和手续费授信。TDC 余额始终要求买家登录，即使商户允许匿名消费也不能匿名使用 TDC。

商户自有 Stripe 渠道需要平台先设置费率。接入分两步：

1. 填写 Stripe 账号资料，点击“保存资料并获取通知地址”。
2. 将该地址添加到 Stripe 的 Webhook 设置，订阅 `checkout.session.completed` 和 `checkout.session.async_payment_succeeded`，将 Signing Secret 填回页面，点击“保存并启用收款”。

完成设置前，买家无法使用该渠道付款。交易前需有足够可用 TDC 或已获批授信支付平台手续费；资金不足或授信不可用会拒绝。自有渠道收款由商户自行到账，TDCloud 不重复记商户钱包收入。

## 买家支付多少，商户收到多少

商品净价等于商品总额减优惠。平台渠道按商品净价结算商户 TDC 收入，买家支付的手续费不计入商户收入。

例如，一笔以 TDC 支付的订单：

| 项目 | 示例金额 |
| --- | --- |
| 商品总额 | 10 TDC |
| 优惠 | 1 TDC |
| 商品净价 | 9 TDC |
| 买家手续费 | 0.27 TDC |
| 买家实际支付 | 9.27 TDC |
| 商户商品收入 | 9 TDC |

这是解释字段的示例，不代表固定费率。实际费用以订单报价为准。

在线渠道使用其他币种时，买家按支付币种付款，商户收入按订单保存的汇率快照结算为 TDC。不要直接把“10 USD 实付”和“10 TDC 入账”画等号，也不要用今天的汇率重新计算历史订单。

## 如何确认到账

打开商户订单检查收入信息，再到“我的钱包”和“交易记录”核对关联订单、收入流水和余额变化。首笔销售不要求商户先充值以创建钱包。

如果订单已经付款但没有对应收入记录，按订单号反馈给平台处理。不要通过修改销量、重复付款或自行增加余额来补账。

## 结算与交付的关系

付款确认和商户入账之后，商品交付仍可能处于处理中。交付重试不应被解释成买家需要再次付款。详细处理见[商户订单与对账](/zh/merchant/orders/)。

当前文档不提供提现或自动退款操作，因为公开页面尚未形成这些完整流程；相关需求请联系平台确认实际处理方式。

## 外部订单的通用收款

已有自己的业务订单时，可使用 [通用商户收款 OpenAPI](/zh/developer/merchant-payments/) 按金额创建收款单，无需创建 TDCloud 商品或要求买家 OAuth 授权。商户服务端可传 `return_url`，买家付款经 TDCloud 确认后返回指定订单页面；商户需通过服务端查单或验证状态通知后幂等更新业务订单。

该能力的平台渠道按建单汇率结算 TDC。平台按商户设置 0–30 天冻结，0 天直接可用。投诉先阻止该单冻结销售款释放，核实后从该单冻结款、担保金、可用余额及待追回余额处理损失；手续费不能返还时，损失可能超出冻结款。退款与拒付状态保留原支付事件，由平台核验并记账。

管理员分配的 Stripe 测试渠道不会向消费者真实扣款，但仍可执行正常钱包 TDC 入账、冻结及交付流程。测试商品和交付由管理员维护。调试授权按商户与付款用户组合匹配：

| 配置 | 可使用此测试渠道的交易 |
| --- | --- |
| 仅填写商户 | 指定商户内的所有买家 |
| 同时填写商户与付款用户 | 指定商户内的指定付款用户，两类条件须同时满足 |
| 仅填写付款用户 | 指定付款用户在所有商户下的交易 |
| 两项都不填 | 无任何调试授权 |

多个编号时，分别匹配商户列表和用户列表中的任意一个。填写付款用户条件后须登录 TDCloud，即使商户允许未登录消费；只填写商户时，未登录消费仍遵循商户设置。钱包充值没有商户归属，须仅填写付款用户、不填写商户。管理员身份不会自动获得调试权限。这些条件只控制所选测试渠道的使用，不会把商户的其他支付渠道自动改为测试。返回地址参数和支付确认流程见 [通用商户收款接入文档](/zh/developer/merchant-payments/)。

## 收款状态通知与补发（可选）

在 **商户中心 → 支付与结算** 的“收款状态通知”设置接收通知的公网 HTTPS 地址。默认关闭，不影响建单或服务端查单。保存地址时生成独立签名密钥，只显示一次；请立即保存到商户服务端，完成验签后启用默认通知。

新收款单可自动使用默认通知，建单时也能指定单笔地址与密钥，或使用 `notify_enabled: false` 关闭单笔通知。更改地址、关闭默认通知和更换密钥只影响新订单；历史通知及补发使用建单时的地址和密钥，接收服务需保留旧密钥。

在同页“收款通知记录”输入 TDCloud 收款单号，可查看订单状态、通知事件号、累计投递次数、HTTP 结果和最近投递明细。每次请求最多等待 8 秒，每轮最多投递 10 次（首次加 9 次递增间隔重试）。自动重试耗尽后可点击“补发通知”重新排队；记录和累计次数保留。

接收服务验签并可靠保存事件后返回 HTTP 2xx 表示确认，重复事件须幂等处理。通知失败不回滚支付或钱包入账。签名、重试间隔及通知参数见 [通用商户收款接入文档](/zh/developer/merchant-payments/#5-服务端状态通知)。
